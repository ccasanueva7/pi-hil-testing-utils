# Device Registry

The dashboard device list is defined in `docs/ci-results/results/devices.json`. This file serves two purposes:

1. Provides display names and metadata for devices that appear in CI job names
2. Adds entries for device types not tracked by the GitHub Actions API (e.g. unit tests)

## File format

```json
{
  "last_updated": "2026-05-13T00:00:00Z",
  "devices": [
    {
      "id": "physical-belkin_rt3200_1-24.10.6",
      "device": "linksys_e8450",
      "display_name": "Belkin RT3200 #1",
      "place": "belkin_rt3200_1",
      "release": "24.10.6",
      "type": "physical",
      "results_path": "physical/belkin_rt3200_1-24.10.6/report.xml"
    }
  ]
}
```

### Fields

| Field | Description |
|-------|-------------|
| `id` | Must match the ID generated by the dashboard JS from the CI job name. Format: `{type}-{place}-{release}` for physical, `{type}-{device}-{release}` for QEMU |
| `device` | OpenWrt device profile name |
| `display_name` | Human-readable label shown in the card title |
| `place` | Labgrid place name (physical devices only, `null` for QEMU) |
| `release` | OpenWrt release string |
| `type` | One of: `physical`, `qemu-single`, `qemu-mesh` |
| `results_path` | Relative path to `report.xml` under `docs/ci-results/results/` |

## Adding a new device

1. Add the device to `targets.yml` in `lime-packages` with `test_firmware: true` and `test_places`
2. Add an entry to `devices.json` following the format above
3. The CI publish pipeline will start populating `report.xml` after the next scheduled run
